# Analyse van code

In het boek heb je gelezen over Big-O (en Theta). Dit is een model om de complexiteit van een programma te analyseren. Hierbij gaat het over de algoritmische complexiteit. Hiermee kun je inschatten over het programma *schaalt* naar bijvoorbeeld grotere datasets. Uiteindelijk gaat het over de resources die nodig zijn om het programma te kunnen runnen.

Er zijn nog andere vormen van complexiteit die een rol spelen bij het programmeren. We gaan ook kijken naar de complexiteit van de code zelf, de tekst van het programma. Hoe complexer code is, hoe lastiger om het overzicht te houden tijdens het programmeren en fouten opsporen. Voor mensen die de code niet eerder hebben gezien kan complexe code ook heel moeilijk zijn om te begrijpen.

Hieronder vind je voorbeelden van programma's of onderdelen van programma's met een bepaalde mate van complexiteit.

|                 | code hoog                | code laag                  |
|-----------------|--------------------------|----------------------------|
| **algo hoog**   | 3D-rendering             | duplicaten in lijst vinden |
| **algo laag**   | beslisboom volgende stap | som van getallen in lijst  |

Hoewel we dus vaak spreken over complexiteit moet uit de context duidelijk worden welke vorm van complexiteit er bedoeld wordt.
